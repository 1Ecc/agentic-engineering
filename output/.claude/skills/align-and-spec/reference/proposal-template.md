# proposal.md 模板

> 落盘位置:`openspec/changes/<topic>/proposal.md`
>
> 由 `align-and-spec` skill 在 N1 需求对齐段产出,沉淀对话痕迹与范围决策。

---

## 模板

```markdown
# <Topic Title> · Proposal

## 背景与动机
<一段话:为什么要做这件事,触发事件是什么>

## 用户故事
- 作为 <角色>,我希望 <行为>,以便 <价值>
- (按需多条)

## 需求探查痕迹
<在 grill 过程中暴露出来的关键点、被排除的方向、未决议题(若有)>

## 范围
**包含**:
- <项>

**不包含**:
- <项>

## 优先级 / 依赖 / 影响面
- 优先级: P0 / P1 / P2
- 依赖: <若无写「无」>
- 影响面: <模块 / 用户群 / 数据 / 兼容性>
```

## 撰写要点

- **背景与动机**:用任务语言,不用纯技术黑话。PM/业务/技术三方都得看得懂。
- **用户故事**:数量不必很多,但每一条都要能映射到 spec.md 里的一个或多个 User Story。
- **需求探查痕迹**:不是聊天纪要,是"经过压力测试后留下的关键事实和被排除的方向"。这是与下一段(spec.md)区别开的关键——proposal 留**过程**,spec 留**结论**。
- **范围**:同等重视"包含"和"不包含"。能写进"不包含"的东西就坚决写进去,这是后续防止范围漂移的锚。
- **优先级**:P0 / P1 / P2 是最简版本,项目有自己约定就用项目的。
