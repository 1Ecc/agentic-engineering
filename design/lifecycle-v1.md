## lifecycle-v1 · 草案 2026-05-22 / 修订 2026-05-24
> 状态：**待用户查验** → 查验通过后再做优化与上锁。

## 0. 基本设定

- **形态**：规划期线性（5 节点）+ 实现期循环 + 验收外部触发
- **三层心智模型**：
  - **artifact 层** = OpenSpec（目录骨架 + spec/delta/archive 机制，本身不含模板内容）
  - **方法论层** = mattpocock/skills + obra/superpowers（TDD / debug 等通用工程方法）
  - **orchestration 层** = 我们写的 skill（`align-and-spec` / `technical-design` / `to-task`），把上面两层在生命周期节点上拼接
- **多轮迭代**：多个生命周期实例叠加，连接器是外部世界（上线 + 用户使用 + 反馈），不进本周期
- **debug**：实现期循环内部的回边，不是独立节点
- **方法论标签**：SDD / TDD 不是阶段，是节点内可选方法论

## 1. 节点表

### 1.1 规划期（线性 · 5 节点 · 我们的主战场）

| # | 节点 | 触发条件 | 输入 | 输出 | 与相邻节点边界 |
|---|---|---|---|---|---|
| **N1** | 需求对齐 | 业务问题/想法被提出（外部触发事件） | 原始想法、业务问题、参考资料、上一轮成品（增量模式） | 需求共识/决策记录（含范围、优先级、核心场景） | 上：触发事件不算节点；下：共识可能是口头/纪要，不是结构化文档，定稿在 N2 |
| **N2** | PRD 撰写 [可挂 SDD] | N1 共识已就位 | N1 共识/决策记录 | 结构化 PRD（AC / 用户故事 / 范围 / 优先级 / 依赖） | 上：不再讨论「做不做」，只整理「做什么」；下：PRD 是 spec，不含技术细节 |
| **N3** | 技术架构 | PRD 已就位 | N2 PRD + 现有系统约束 | 系统骨架（组件组织、数据流、部署结构、模块边界） | 上：不选具体技术栈；下：架构定型后再选具体技术 |
| **N4** | 技术方案 | 架构已就位 | N3 架构 + 可选技术池/约束 | 具体技术方案（技术栈、API、关键库、组件选型） | 上：架构已定不重讨论；下：方案完成进 plan 编排 |
| **N5** | 任务拆分 | 方案已就位，需要可执行步骤 | N4 方案 + agent 能力评估 | `tasks.md`（顺序 / 依赖 / checkpoint / 可并行标记，每条即可独立领取的任务粒度） | 上：不重讨技术选型；下：清单完成开始执行 |

### 1.2 实现期（循环 · 不强分节点 · 复用现有方法论 skill）

实现期 = `开发 ⇄ 测试 ⇄ debug/联调` 的小循环，由 N5 的 `tasks.md` 驱动，循环退出条件 = `tasks.md` 全部勾完 + 验收通过。

| 子活动 | 方法论 | 产物落点 |
|---|---|---|
| 开发 + 测试 | mp/`tdd`（红绿循环 + tracer bullet + 反 horizontal slicing） | 代码本体 + 单元测试 + `tasks.md` 状态更新 |
| debug / 联调 | own/`diagnose`（建反馈回路 → 复现 → 3-5 个可证伪假设 → 插桩 → 修+回归 → 清理&落盘&复盘） | `openspec/changes/<name>/issues/<topic>.md`（无固定模板，按本次诊断自然写） |

### 1.3 验收（终点 · 外部触发）

验收 = 测试全过 + AC 比对 + 用户签字。archive 行为（把 `changes/<name>/` 搬到 `archive/`、合并 delta 到顶层 `specs/`）**由项目 CLAUDE.md 规定**，本方法论不约定具体怎么触发、由谁触发。

## 1.4 节点 ↔ skill 映射

> **来源标识**：**sp**=obra/superpowers · **mp**=mattpocock/skills · **loc**=本地/业务定制 · **own**=本项目自写
> **读法**：规划期我们已经写了 own orchestration skill 把对应方法论吸收进来，运行时只调 own skill 即可，不再触发外部方法论 skill；实现期没有 own skill，直接调方法论 skill。

### 规划期

| 节点 | 调用的 skill | 备注 |
|---|---|---|
| N1 需求对齐 | own/`align-and-spec` | skill 内已吸收 brainstorming / grill-me / grill-with-docs / to-prd 的思路 |
| N2 PRD 撰写 | own/`align-and-spec`（同 skill 覆盖 N1+N2） | spec 模板参考自 mp/to-prd |
| N3 技术架构 | own/`technical-design` | skill 内已吸收 improve-codebase-architecture / zoom-out / brainstorming / prototype 的思路 |
| N4 技术方案 | own/`technical-design`（同 skill 覆盖 N3+N4） | 同上 |
| N5 任务拆分 | own/`to-task` | skill 内已吸收 writing-plans 的思路 |

### 实现期

| 子活动 | 方法论 skill |
|---|---|
| 开发 + 测试 | mp/`tdd` |
| debug / 联调 | own/`diagnose` |


## 2. 节点内双模式

每个节点的 skill 自动根据「有无旧产物」切换：

- **from-scratch 模式**：第 1 轮，从零写
- **incremental-update 模式**：第 n 轮，读旧产物 → 标变更 → 增量更新
