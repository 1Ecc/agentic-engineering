# 项目定位与简历证据

核对日期：2026-10-07。用途：简历与面试介绍；不定义产品行为，也不取代 handoff.md。

## 定位

基于成熟开源实践进行场景化改造，面向个人与小团队统一 SDD、TDD、上下文持久化、技能路由及工具交付。可证明的是集成设计与工程落地，尚无对照实验证明整体效果优于四个上游。

结合 [培训配图梳理](../AIcoding_teaching/配图梳理.md) 图 3a 与用户补充，叙事应从真实协作问题出发：需求偏移、跨会话状态丢失、验证不足、经验难复用；评估四类实践的强项和适用边界，再结合自身工程经验裁剪、改造，形成 SDD + TDD + 生命周期节点 Skills。突出方法设计、适用性判断与经验抽象能力，避免只呈现为技能集合的安装整合。

表述“各有侧重，单独采用不能完整满足自身的 AI Coding 协作约束”，不泛化为“不适应现在的 AI Coding”。这些上游本身就面向 AI 编程；培训稿中的“偏重”等判断应限定为本项目的使用体验与取舍。

对比为官方 README 与本地实现的定位分析，不代表功能穷举或性能排名。上游会持续演进；候选池数字只描述当时的本地选型记录。

## 可展示的设计能力

- 工作流编排：明确节点的输入、产物、后继与验收反馈；统一不同来源 Skills 的协作约定。
- 上下文工程：Spec 保存需求与设计，INDEX 保存结构索引，Handoff 保存最新会话快照；规则按职责渐进披露。
- 请求路由：新需求、已有需求缺陷、续作分别分流；问答、快修和一次性脚本可直接执行。
- 经验回流：review 将发现路由到 PRD、Design、ADR 或可复用方法候选；升级通用规则需用户确认。
- 工具交付：零运行时依赖 ESM CLI，项目级安装、平台识别与选择、幂等初始化、保留已有布局和文件。

## 尚不能作为业绩使用的数值

未找到开发提效、Token 节省、返工减少、跨会话恢复成功率、培训人数和实际采用率的实测数据。不要用技能数量变化推导性能提升，也不要把上游 Stars 当作本项目影响力。

门禁目前主要通过 Skill 指令约束，并非运行时强制拦截。Router 自动触发和各平台实际加载仍需真实会话验证；index-rebuild 尚未实现。不宜宣称彻底解决跨会话失忆、保证自动路由或全自动状态管理。

## 后续效果测量

固定模型版本、任务与验收标准，对比基础 Agent 与 AE 工作流，记录任务类型、重复试验次数和失败结果；优先统计首次验收通过率、人工纠偏次数、跨会话恢复耗时、端到端交付耗时与 Token 成本。小样本报告原始计数，不推广为通用收益。

组织赋能另行记录培训场次、去重人数、培训后实际采用人数、落地项目数和业务 Skill 复用次数。这些数据更适合证明团队影响力。

培训稿图 4a 已提供业务分析素材：梳理 4 个业务需求，识别 6 类共享节点，每类关联 2 个需求；其中 4 类归为标准件复用，2 类归为方法复用。这能支持“从 4 个业务需求中抽象出 6 类共享节点，区分标准件与方法复用”的表述。它是梳理范围内的复用分析，不是已部署 6 个 Skills、全部节点复用率 100% 或开发提效 50% 的证明；图 4b 的集团平台推广与对外产品化应与已落地成果分开。

## 简历参考

基于 Superpowers、OpenSpec 等 4 个开源项目的实践，面向个人与小团队设计并发布 Agentic Engineering；从 43 个候选 Skills 中选型，结合自定义路由与编码纪律形成 14 个 Skills，统一 SDD→TDD→真实路径验证工作流，以 Spec/INDEX/Handoff 支持跨会话状态接续；实现零依赖 npm CLI，支持 15 种 AI Coding 平台的项目级安装，并通过 29 项自动化测试验证 CLI 行为。
