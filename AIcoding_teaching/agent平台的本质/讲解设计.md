# coding 本质 · 讲解设计（开场 ~20 分钟）

> 本文件是「怎么讲」的剧本：定位 → 脊柱 → 逐步脚本 → 累积心智模型 → 收尾落点 → 成功标尺 → 配图清单。
> 代码与运行见 `demo/`，本文件只管表达与节奏。

## 0. 一页纸定位

| 项 | 内容 |
|---|---|
| 位置 / 时长 | 整场 1 小时的**开场 ~20 分钟**；之后接 agentic engineering 工程方法论 |
| 听众 | 混合人群：研发 / 业务 / 产品管理 |
| 语气 | **赋能**（不是炫技、不是吓唬） |
| 脊柱 | ①**祛魅**：agent = 模型 + 循环 + 执行命令；②**赋能**：模型能干多少，取决于你喂给它什么 |
| 压轴落点 | **②** —— 落在「上下文 / 说明书决定能力」，并交棒给 **AI IDE** |
| 成功标尺 | 离场时能用大白话复述 agent 循环 + 对「喂什么决定它能干什么」「价格/质量/时间的权衡」有直观感 + 想去试 AI IDE |

## 1. 两段式结构（脊柱怎么落地）

```
段A · 机理（祛魅）          段B · 做事（赋能）            收尾 · 接缝
[1 chat]→[2 单次API]→       [5 agent化]→[6 +skill/mcp]→   上下文管理
[3 循环无记忆]→[4 多轮记忆]   [7 小龙虾]                    → 价格/质量/时间
                                                          → 交棒 AI IDE
   "它没记忆、要你喂"          "给说明书/接能力就脱胎换骨"     "谁帮你喂得又准又省"
```

- **段A（约 7 min）**：把大家天天用的 chat 拆开，看清「模型怎么调用、记忆是怎么回事」。落点是祛魅——它本身没记忆、不会动手。
- **段B（约 7 min）**：从「能做事」到「做得好」，引出 agent 循环 + 说明书 + 外部能力。落点是赋能。
- **收尾（约 4–5 min）**：东西越喂越多 → 上下文管理 → 为什么需要工程化平台 / AI IDE。

## 2. 逐步脚本：演示动作 → 揭示的见解 → 那一句话

| # | 步骤（对应 demo） | 现场演示动作 | 揭示的见解 | 那一句话（口播落点） |
|---|---|---|---|---|
| 0 | chat 引子 | 打开 DeepSeek/ChatGPT 网页问一句 | 大家天天用的 chat，就是在跟一个「问答函数」聊天 | 「今天我们把这个对话框拆开，看里面到底是什么。」 |
| 1 | 单次 API（`step1`） | 跑 step1，一次问答 | 网页背后就是**一次 API 调用**，照官方示例填 model / messages 就行 | 「网页是给人看的壳，API 才是给程序用的入口——就这么几行。」 |
| 2 | 循环·无记忆（`step2`） | 你好 → 1+1 → 再加 1（**翻车**） | 模型本身**没有记忆**，每次只看到你当前这句 | 「它不是失忆，是你根本没把上文告诉它。」 |
| 3 | 多轮·有记忆（`step3`） | 同样追问成功 + 问「刚才说了啥」 | 记忆 = **把历史原样再喂回去**；此刻已和网页聊天无异 | 「所谓记忆，就是每次把账本翻给它看一遍。」（埋钩：账本会越翻越厚） |
| 4 | agent 化（`step4`） | 「创建 hello.txt」成功；再试「今天天气」→ 不稳定 | 一份**说明书**（system：回命令/回完成）+ 一个**循环**（执行→喂回→再判断），agent 就诞生了 | 「agent 不神秘——它就是一个会自己跑命令的 while 循环。」 |
| 5 | 装 skill / 接 mcp（`step5`、`step5_mcp`） | 装 skill 查天气（稳了）；再用 mcp 做同一件事 | 模型不会的，**你提前把怎么做告诉它**就会了。skill=把本机做法写给它；mcp=给它接外部标准能力 | 「不是它厉害，是你厉害——同一只模型，给说明书 / 接能力，立刻脱胎换骨。」 |
| 6 | 小龙虾（`step6_web`） | 手机远程发任务，本机执行 | 换皮（网页/手机）只是**壳**，内核还是那个 agent 循环；稳不稳取决于内核 | 「大众眼里的『龙虾』，就是这个内核 + 一层好看的皮。」 |

## 3. 累积心智模型（每讲一步，往同一张图上加一块）

讲解时**始终用同一张图**，逐步「长出来」——这是让混合人群不掉线的关键。

```
step1   [ 模型 ]  问 → 答
step2   [ 模型 ] + (while 循环)
step3   [ 模型 ] + 循环 + [ 历史 messages ]
step4   [ 模型 ] + 循环 + 历史 + [ 说明书 system ] + [ 执行命令 ]      ← agent 成形
step5   …………………………………… + [ skill 说明书 ] + [ mcp 外部能力 ]
step6   …………………………………… + [ 一层皮：网页 / 手机 ]
```

收束成一句：**agent = 模型 + 循环 + 执行命令 + 一份说明书**（其余都是给它喂的「料」和外面的「皮」）。

## 4. 收尾：上下文管理 → AI IDE（赋能落点，最后 4–5 分钟）

**第一步：把这趟 demo 里"喂给模型的东西"摆出来**，让大家直观感到「越喂越多」。

- 今天 demo 里已经出现（实）：`system prompt` / `user prompt` / 历史记录 / skill 说明 / mcp 工具说明 / 命令执行结果。
- 等你真做 aicoding 还会加上（虚）：入口规则文件（`AGENTS.md` / `CLAUDE.md`）、skills 摘要索引、说明文档、**代码文件**……

**第二步：为什么"越喂越多"是个问题？——打三个最敏感的点（价格 / 质量 / 时间）**

| 维度 | 现象 | 大白话 |
|---|---|---|
| 💰 价格 | 每轮都要把历史重发，input token 随轮次累积，**总花费加速上涨** | 「越聊越贵，而且是加速变贵。」 |
| 🎯 质量 | 上下文越长，模型注意力越稀释，关键信息淹没在噪音里（业界叫 *lost-in-the-middle*） | 「喂太多，它反而抓不住重点。」 |
| ⏱️ 时间 | 上下文越长，每次推理算得越久 | 「越长越慢。」 |

> 一句话收口：**「喂什么、什么时候喂、怎么压缩和检索」——这件事就叫上下文管理。**

**第三步：交棒 AI IDE（回环金句）**

- 一句概念名：模型外面这层「壳」(上下文管理 + 工具 + 权限 + 反馈环) 叫 **harness**，把它做好就是 **harness engineering**——**Agent = Model + Harness**。「大多数 agent 在生产里失败，不是模型弱，是 harness 脆。」
- 所以需要把这件事**工程化**的平台 / AI IDE：**claude code、codex、workbuddy** 等——它们帮你管上下文、调度 skills/mcp、管权限和安全，还提供很多个性化能力。
- 📎 论证与证据（自动压缩/记忆工具/沙箱权限等，带出处）见 `为什么需要agent平台.md`。
- 回环（呼应 step1）：**「别怕，这些平台底层也就是 step1 那个调用——没订阅时你甚至能换别的模型自己接，跟我们今天写的一模一样。」**
- 交棒下一段：**「接下来我们就讲，怎么用这些平台把今天这套东西用好——agentic engineering。」**

## 5. 成功标尺（讲完怎么算"成了"）

听众离场时应该能做到：
1. 用大白话**复述 agent 循环**（模型回命令 → 执行 → 喂回 → 再判断）。
2. 对「**喂给模型什么，决定它能干什么**」有直观感（prompt / skill / mcp）。
3. 对「上下文越多 → **更贵 / 更慢 / 可能更差**」的权衡有感觉。
4. **产生想去试 AI IDE 的冲动**（赋能落点达成）。

**图3 · skill 机理图（用户输入 → 调用实现）**
- 流向：`用户输入任务` → `命中 skill 说明（这类任务该怎么做）` → `模型按说明产出一条命令/步骤` → `本机执行` → `结果喂回模型` → `模型给出回答`。
- 一句话注脚：skill = **把"本机已有的做法"提前写给模型**。

**图4 · mcp 机理图（用户输入 → 调用实现）**
- 流向（简化版，价值+机理兼顾）：`用户输入任务` → `Host 把可用工具清单给模型` → `模型发出 tool call（要调哪个工具、什么参数）` → `Host 经 MCP Client 调用 MCP Server` → `Server 执行真实操作（天气/GitHub/数据库…）` → `结果回填模型上下文` → `模型回答`。
- 一句话注脚：mcp = **给模型接上"外部标准能力"**；模型只发意图，真正干活的是 Server。
