# 模块：coding 本质（培训第一章节）

本模块通过一组**可现场运行、逐步演进**的 case，让混合人群（研发 / 业务 / 产品管理）
理解这条链路的本质：**大模型 LLM → 模型 API 接口 → 智能体 agent → 龙虾 openclaw**。

> 主线一句话：**agent = 大模型 + 一个循环 + 执行命令 + 一份说明书（提示词 / 技能）**

## 目录结构

- `讲解设计.md` —— **怎么讲**的剧本：~20min 开场、脊柱、逐步脚本、上下文管理收尾、配图清单
- `为什么需要agent平台.md` —— 收尾论证 + 证据：harness engineering、上下文管理、claude code / codex 工程成熟度（带出处）
- `参考文案.md` —— 选题来源（飞天闪客「20 行代码搞懂小龙虾」口播稿）+ 演进思路
- `demo/` —— 演示工程，从单轮脚本一路长成网页版小龙虾
  - 进一步细节见 `demo/README.md`（讲师手册：6 步演进表 + 每步「那句话」 + 收尾钩子 + 风险提示）

### 实现agent
实现能操作本地文件的agent（step4_agent.py）。
以「创建一个文件」为切入点，引出所有人都会问的问题：agent 到底能干什么？我为什么要用它？
答案：agent 几乎可以做任何事 —— 因为任何操作都能用一条命令表示；即使一条命令搞不定或太复杂，
那就让模型「写一段脚本，再执行它」。所以才有那句主线：**万物皆可命令 = 万物皆可 coding**。

> 现场可再补一个贴近日常的简单例子，例如：
> 任务 > 把这篇文章 https://mp.weixin.qq.com/s/8bxXqS2R8Fx5-1TLDBiEDg 下载到本地

#### 串讲 1 · 说明书外接 + system / user 两种角色（对应 step4）
1. **把系统提示词从代码里抽到外接文件**：step4 不再把 system 写死在 `.py` 里，而是
   `open("AGENTS.md").read()` 读进来。代码只剩「循环 + 执行」，规矩都在外接文件里。
2. **命名特意用 `AGENTS.md`**（不是 agent.md）：这正是 Claude Code / Codex 等工具的
   **入口规则文件**（`AGENTS.md` / `CLAUDE.md`）。现在手搓的这份，和后面平台自动加载的那份，
   是同一个东西 —— 这条线串起来，后半程「为什么用工程化平台」就顺理成章。
3. **强调两种角色的区别**：
   - `system`（说明书）= 定规矩、立人设，整段对话只设一次，放最前面。
   - `user`（任务）= 每一轮提的具体需求。
   - 让观众看出：agent 的「行为约束」来自 system，「干什么」来自 user。

#### 串讲 2 · 从「翻车」引出 skill / mcp / 插件（对应 step5，并埋下一章伏笔）
**入手：先让 agent 翻一次车。** 给一个 step4 的裸 agent 搞不定的任务，让缺陷自己暴露：
- 例：`任务 > 帮我查一下今天最新的新闻`。模型受训练知识范围限制，要么一本正经地编一条过时消息，
  要么压根不知道该调什么命令 —— 这就是「不知道怎么做 / 做得一塌糊涂」。

**补救：本质都是『提前把该怎么做告诉它』，按粒度分三档：**
1. **skill** —— 一份「操作说明书」：告诉模型「遇到 X 场景，就用 Y 命令 / 这套步骤」。
   就是 step5 的 `skill.md`（查实时天气用 `curl wttr.in`）。装上它，同一只龙虾立刻会干活了。
   注意挑案例：别用「下视频」（模型本就会 yt-dlp，显不出 skill 价值），要用模型靠记忆做不到的实时类任务。
2. **mcp** —— 外部提供的「标准化工具 / 服务」：比如实时搜索、数据库、内部系统，模型按统一协议去调。
   skill 是「教它用本机已有的命令」，mcp 是「给它接上一个新的外部能力」。
   👉 **可演示**：`demo/step5_mcp/` 把同一个「查天气」改成 MCP 工具来做，和 step5 的 skill 版对比着讲
   （server = 一个函数 + 一个 `@mcp.tool()`；client = 连服务→列工具→模型按名字调用）。
3. **插件** —— 把多个 skill / mcp 打包串联成一个现成的能力集。

**顺势抛出两个待解问题（不在本章解决，留作第二章钩子）：**
- mcp 更像是**全局加载**：一上来全挂上，能力齐全但持续占用上下文。
- skills 更像是**渐进式披露**：用到才加载，省上下文但要有调度逻辑。
- 谁来管这些加载、占多少上下文、会不会互相打架 —— 正是工程化平台要解决的问题。

**本章先做最朴素的处理：** 不纠结加载策略，统一把 skill 当作 `system` 提示词直接拼进去
（就是 step5 `system = AGENTS.md + skill.md` 的做法）。先让大家看清**本质**，
真正的「怎么加载、怎么调度」交给第二章的 Codex / Claude Code。

## 呈现形式（已定）

混合式：以「现场跑一个能用的 demo」为主轴，复刻参考视频「亲手一步步实现」的节奏；
代码露出按「关键几行 + 心智模型」控制，让研发看得过瘾、业务 / 产品不掉队。

落地规范：
1. **每步先看 diff、再运行**：开讲每一步时，先点出「它只比上一步多了这几行」（while / messages /
   读 AGENTS.md / 执行命令），再实跑。逐步迭代的「长出来」感，是这一章的核心体验。
2. **统一终端输出格式**，让非技术人也能读懂对话流：
   - 对话类（step1-3）：`你：…` / `AI：…`
   - agent 类（step4-6）：`任务 >` → `---- Agent 循环开始 ----` → `[AI] …` →
     `[执行] <命令>` / `[结果] …` → `---- Agent 循环结束 ----`
3. **两条视线并行**：研发盯左边的代码 diff，业务 / 产品盯右边终端的「对话感」和每步那句话。
4. **现场兜底**：每一步提前录屏；真机演示失败就切录屏，节奏不断。依赖网络的 case
   （step5 实时天气、step6 网页版）优先用录屏，现场只复述。
5. **安全与密钥**：key 走 `.env` 环境变量、不出现在屏幕代码里；step4-6 只在隔离 / 测试目录跑
   低风险任务。
