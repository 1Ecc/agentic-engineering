# 第二章讲解设计 · 为什么需要工程化平台（~15 分钟）

> 怎么讲的剧本。功能细节现场在 claude code / codex 里实操，本稿只给脊柱、话术顺序、演示清单。
> 论证与出处复用 `../coding本质/为什么需要agent平台.md`，此处不重抄链接。

## 脊柱（一句话）

第一章你们亲手看到：那个 agent **没记忆、上下文有限、直接跑 shell 没护栏**。
把这层「壳」做稳做强 = **harness engineering**；claude code / codex 的价值**不在模型，在这套成熟工程**。

> 回环金句（从第一章带过来）：平台底层也就是 step1 那个 API 调用——没订阅也能换个模型自己接。值钱的是外面这层壳。

## 逐段话术

### ① 过渡（~1 min）：几十行 vs 几十万行 + 接住第一章的「痛」
不要重新介绍 agent。先抛**矛盾钩子**，再点名第一章暴露的三个痛点：

> **钩子**：第一章你几十行就跑出了 agent；可 2026 年 3 月底 Claude Code 打包源码被反编译，发现是**几十万行量级**（14 万+明文字符串，minify 不是加密、其实一直随 npm 包发）。**几十行能跑的东西，凭什么要写几十万行？那多出来的，就是今天讲的 harness。**

1. **越喂越多** → 又贵、又慢、还会 context rot（注意力被稀释，答得更差）。
2. **越跑越危险** → step4–6 直接执行模型返回的 shell，没有任何护栏。
3. **越复杂越不稳** → 工具、记忆、多步骤一多，手搓脚本就崩。

一句收口：「这三件事，自己写脚本都能凑合，但要**天天用、给团队用**，就需要把壳做成工程——这就是平台。」

### ② 三块能力（~9 min，本章主体，边讲边在平台里点）
把三个痛点一一对上平台能力。**每块讲完立刻在 claude code / codex 里现场点一下**，让大家看到「这不是 PPT 概念」。

| 痛点 | 平台怎么解 | 现场演示锚点（见下方清单） |
|------|-----------|---------------------------|
| 越喂越贵越慢 | **上下文管理**：自动压缩、可见可控、子代理/按需检索 | `/context`、压缩提示、subagent |
| 越跑越危险 | **权限与沙箱**：分级权限、默认无网/限工作区、按需审批 | 权限模式、危险命令弹确认 |
| 越复杂越不稳 | **工具生态**：skills / MCP / 插件 可插拔、可复用、可分发 | 调一个 skill 或 MCP、列工具 |

讲法提醒：
- 上面演的是三块；**完整 harness 是四块**：上下文管理 / 能力接入 / **规划与调度** / 安全权限——「规划调度」现场口播带过即可。
- 上下文这块只点「价格/质量/时间」三敏感，不展开 messages 内部（第一章已祛魅过）。**想深挖**可上「上下文压缩四档阶梯」（micro-compact → auto-compact → `/compact`·`/clear`·`/btw` → 兜底），见 `为什么需要agent平台.md §2①` 与配图 **图2b**。
- 工具生态直接呼应第一章 step5（skill）和 step5_mcp（MCP）：「你手搓那两个，平台帮你管好了加载、调度、复用。」
- 安全这块呼应第一章 step4–6「裸跑 shell」的风险，对比平台的护栏。

### ③ 快速上手：平台选型 + 没订阅怎么办（~2 min）

把「值钱」落到「我现在怎么用起来」，给一条最短路径（递进三步）：

1. **搭一个 agent 平台**：**Claude Code** 或 **Codex**——开箱即用的成熟 harness，前面讲的上下文/权限/工具三块它都替你管好了。
2. **没有官方订阅？** 用 **cc switch** 把平台后端切到**国产模型 API**，照样跑。呼应回环金句：*底层也就是第一章 step1 那个 API 调用，换个模型自己接而已。*
3. **国产模型怎么选**（按需取强项）：

   | 模型 | 强项 | 什么时候优先它 |
   |------|------|----------------|
   | **GLM-5.2** | **Coding 能力最强** | 写代码 / 干工程活 |
   | **DeepSeek V4 Pro** | **世界知识最强** | 广博知识 / 通用问答 |

> 一句带过即可：「平台不绑模型——有订阅用官方，没订阅 cc switch 接国产；写代码偏 GLM-5.2，要知识偏 DeepSeek。」

### ④ 收口 + 交棒（~2 min）
- 一句总结：**Agent = Model + Harness**；模型谁都能调，平台赢在 harness。
- 交棒第三章：「光有好工具不等于会用——下一段讲怎么把它放进真实工程流程：**SDD 管做什么，TDD 管做对**。」

## 现场演示清单（你来实操，建议顺序）

> 在隔离/演示目录里跑，别在生产仓。讲到哪点哪个，点不动就口播带过，别卡壳。

- [ ] **上下文可见**：`/context` 看占用分类；提一句「接近上限会自动压缩，保留决策、丢冗余输出」。
- [ ] **子代理 / 渐进披露**：开一个 subagent 或展示「只读文件路径、按需读取」的效果（回传摘要而非全文）。
- [ ] **工具能力**：调用一个 skill 或一个已接的 MCP（如查询、GitHub、内部系统），让大家看到「能力是插上去的」。
- [ ] **权限与安全**：触发一次需要审批的操作（联网 / 写文件 / 危险命令），展示弹确认；对比第一章裸跑 shell。
- [ ] **（可选）插件 / hooks**：一句话带过「团队能力可一键安装、统一分发」。

每个动作配一句话即可，不必讲全部参数——本章目的是建立心智，不是教按钮。

## 跨人群翻译

| 工程词 | 给非研发的说法 |
|--------|----------------|
| harness | 模型外面那层「工作台」，决定它能不能稳定干活 |
| 上下文管理 | 控制「给 AI 看多少东西」——直接影响贵不贵、准不准、快不快 |
| 沙箱 / 权限 | 给 AI 划安全围栏，越界要先举手批准 |
| skill / MCP | 给 AI 插上「会用某个工具 / 连某个系统」的能力卡 |
| 插件 | 把团队的能力打包，一键装给所有人 |
