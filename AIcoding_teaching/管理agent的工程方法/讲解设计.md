# 第三章讲解设计 · 管理 agent 的工程方法（~15 分钟）

> 怎么讲的剧本。**现场在 sandbox 里用本仓 `ae` 实操**，本稿只给脊柱、贯穿 case、逐节点话术、现场清单、兜底。
> 方法论本体见仓库根 `docs/framework.md`（S0/S1/S2、SDD+TDD、节点 skill 清单），此处不重抄。

## 脊柱（一句话）

第二章你们看到平台把「壳」做成了工程。但**光有好平台不等于会用**——
真正决定结果好坏的，是 **你怎么管理 agent**：先对齐、再落 spec、再拆步、TDD、验证、handoff、沉淀。

> 金句：**AI coding 的核心，不是「我去 coding」，是「我把 agent 管好」。**
> 一句方法论：**SDD 管做什么，TDD 管做对。**

不要讲抽象方法论。**全程围绕一个真实产品现场造一遍**，让方法自己长出来。

## 贯穿 case（这一章自始至终就造这一个产品）

**任务：现场开发一个产品 —— Knode v0，一个团队内部的「skills hub」。**

它能把本地 `.claude/skills` **同步**出来，能逛**广场**（团队/集团共享的节点），能搜索、看详情、「下载」。
**它就是第四章 Knode 的雏形**——这一章把它真的跑出来，第四章再讲它能长成什么生意。

> **为现场稳定性而定的形态（重要）**：**纯前端 `index.html`（零构建）+ 只读轻量服务**（一个同步脚本扫 skills→json，一个 `python -m http.server` 静态服务器）。
> **不写盘、不建库、无自写后端 API**——现场没有会崩的长运行服务，真崩了直接开 HTML 兜底。

现场你（讲师）只打这一句 **故意模糊** 的需求：

```text
帮我做一个 Knode —— 一个团队内部的 skills hub。
先做个纯前端小页面：把本地 .claude/skills 同步出来展示，
再加一个「广场」能逛团队/集团共享的节点，能搜索、看详情、下载。
广场数据先用 demo/plaza_nodes.json，存储就用本地 json、别上数据库。
```

**为什么选这个 case（讲师心里有数即可）：**

- **是个真产品，不是脚本**：有页面、有同步、有「广场/下载/安全徽章」板块——现场从零造出一个能用的东西，最像真实开发。
- **够模糊**：做哪几个板块、**砍掉哪些**？「下载」要不要真写盘？「上传」做不做？同步怎么解析、怎么去重？——逼出「对齐 + 砍范围」，这是做产品最该练的。
- **稳 + 快**：纯前端只读，没有后端/数据库的现场风险；范围砍干净后，15 分钟跑得完。
- **可验证**：同步解析、搜索、安全徽章都是纯函数，能写测试断言「做对没有」——TDD 的天然舞台；UI 能当场打开验收。
- **首尾呼应**：本地同步的就是 `ae setup` 刚装的 skills（吃自己狗粮）；广场第一条就是 `powerautomate-email-to-sharepoint-excel`（第四章 Exhibit A）→ 直接交棒第四章。

> 道具已备好：`demo/plaza_nodes.json`（广场 4 张：邮件抓取 / 格式整理 / 接口补字段 / 驱动后台，含 `scope` 团队·集团）+ `demo/产品说明_v0.md`（v0 范围 + 数据模型 + 验收标准，**讲师手里的标准答案**，**别一上来甩给 agent**）。

## 逐段话术（边讲边在 `ae` 里跑）

### ① S0 Bootstrap（~1.5 min）：先把「地基」立起来

在一个空 sandbox 目录里：

```bash
ae setup            # 装方法资产：节点 skill 进 .claude/skills、.codex/skills
ae init "Knode 节点库 v0"   # 渲染骨架：AGENTS.md / spec/ / handoff.md
```

一句话带过：**「这一步只做一次，等于给 agent 立项目规则、可用工具、任务入口。」**
顺手点一句：**「`ae setup` 刚把一批 skill 装进 `.claude/skills`——待会我们造的 Knode，第一件事就是把它们同步出来。」**

### ② Router（~0.5 min）：不是每个请求都值得走流程

提一句 `using-agentic-engineering` 路由器：**问答 / 快修 / 一次性脚本直接做；只有「构成需求」的才进主循环。** 做产品要可维护、要扩展、要交接——所以它**值得**走一遍完整循环。

### ③ S1-A 需求场景（~6 min，本章高光）：先对齐 + 砍范围，再动手

| 节点 | 现场动作 | 那句话 |
|------|----------|--------|
| **A1 对齐**（`brainstorming` + `grill-me`） | 打出上面那句模糊需求，**别让它直接做**。看 agent 反问：要哪几个板块（我的节点 / 广场 / 搜索 / 详情 / 下载 / 安全徽章）？**「下载」是真写到本地 skills 目录吗**？**「上传/投稿」v0 做不做**？同步怎么读 frontmatter、坏的跳过吗、按什么去重？存哪（本地 json，不建库）？ | 「做产品最贵的能力是**砍范围**。下载先不写盘、上传直接砍、登录权限全不做——v0 能用就行。让它先复述 + 列验收标准，比快快做出来重要得多。」 |
| **A2 写 PRD**（`to-prd`） | 把对齐结论落成 `spec/needs/knode-v0/prd.md`：数据模型、v0 板块（做/不做）、验收标准 | 「**spec = 先把『要什么、不要什么』白纸黑字写下来。** 这就是 SDD。」 |
| **A3 写设计**（`writing-plans`） | 生成 `design.md`：**纯前端** `index.html`（卡片 + 搜索 + 来源过滤 + 详情 + 下载 + 安全徽章）+ **同步脚本**（扫 `.claude/skills` 读 frontmatter → `skills.json`）+ **静态服务器**（`python -m http.server`）+ 广场数据来自 `plaza_nodes.json` | 「**只读、不写盘、不建库**——这就是为什么它现场稳。给业务/产品看的是这页，不是代码。」 |
| **A4 拆步**（`to-issues`） | 生成 `todo.md`，拆成 4–5 步（同步脚本 → 数据加载 → 搜索/过滤 → 详情/下载/徽章 → 联调） | 「大产品拆小，每步都有可检查的产出。」 |

> 现场判断对齐是否到位：对照 `demo/产品说明_v0.md` 那张「标准答案」。agent 问到了板块取舍、问到「下载写不写盘」「上传做不做」、问到同步去重和存储 → 对齐成功，可以往下。

### ④ S1-A 实现 + 验证（~4 min）：怎么证明这产品做对了

| 节点 | 现场动作 | 那句话 |
|------|----------|--------|
| **A5 TDD**（`tdd`） | 让它**先写测试再写实现**（**全是纯函数**）：①一段 frontmatter → 节点，缺 `name`/`description` 跳过、按 `id` 去重；②搜 `email` 命中 `powerautomate`；③`pitfalls` 含「凭据/shell/驱动」→ 安全徽章「需注意」。**先红后绿**。 | 「**test = 先定义『怎样算做对』。** 红→绿这一下，就是『做对』的证据。」 |
| **A6 验证**（`verification-before-completion`） | 起静态服务器、**当场打开网页**：列出本地同步若干张 + 广场 4 张 → 搜 `email` 命中 → 来源切「集团」只剩集团卡 → 点「下载」加入清单/弹安装命令 → `接口补字段`/`驱动后台` 显示「需注意」徽章 | 「**别信『我做完了』，信『你看，网页上点出来是这样』。** 非技术同事也能验收。」 |

### ⑤ Handoff + S2 沉淀（~2 min）：把这次变成下次的起点

- **handoff**（`handoff` skill）：覆盖写 `handoff.md`——当前态 + **关键决策**（纯前端只读、下载=加清单不写盘、上传/深度安全/写盘安装砍到后续、按 `id` 去重）+ 下一步。
  > 「**handoff = 把当前状态写下来，下一轮能接上。** 别把项目状态只留在聊天窗口里。」
- **S2 沉淀**：**你刚现场跑出来的就是 Knode v0** → 交棒第四章：「下一章讲，这个雏形怎么长成团队的节点库、组织的共享平台，乃至一门生意。」 **（交棒第四章）**

## 隐藏验收标准（讲师 cheat-sheet，对照 `demo/产品说明_v0.md`）

一次「好的对齐 + 好的实现」应当落到：

- 形态：**纯前端 `index.html` + 同步脚本 + 静态服务器**，只读、不写盘、不建库
- v0 **只做** 本地同步 / 广场（来源过滤）/ 搜索 / 详情 / 下载（加清单不写盘）/ 安全徽章（轻量）
- v0 **明确砍掉** 上传投稿 / 真写盘安装 / 深度安全扫描 / 登录权限多人 / 编辑删除
- 校验：同步缺 `name`/`description` 跳过、按 `id` 去重；搜索命中 `name`/`when`/`tags`；含「凭据/shell/驱动」→「需注意」
- 验收：本地+广场列出 → 搜 `email` 命中 → 切「集团」过滤 → 下载加清单 → 风险节点带徽章

只要现场结果命中这几条，就证明「管理 agent」这套方法把一个模糊的**产品**需求做对了。

## 跨人群翻译（落场时反复用）

| 工程词 | 给非研发的说法 |
|--------|----------------|
| spec / PRD | 先把「要什么、不要什么、怎样算合格」说清楚 |
| 砍范围 | 先定 v0 边界，别一口吃成胖子 |
| 纯前端 / 只读 | 就一个网页，不写你电脑里的东西，所以稳 |
| test | 先定义「怎样算做对」，再让它做 |
| handoff | 把当前状态写下来，下一轮能接上 |
| skill | 把踩过坑的优秀做法写成可复用卡片（Knode 里逛的就是它） |

## 兜底与风险

- **现场实跑有不确定性**：A1 对齐、A5 红绿、A6 网页验收三步**提前录屏**；真机卡了就切录屏，节奏不断。
- **纯前端只读已经是最稳形态**：万一静态服务器起不来，直接用浏览器开 `index.html`（广场 json 可内联兜底）。
- **课前先把栈定死**：`index.html` + 同步脚本（Python 或零依赖 Node，正则读 frontmatter）+ `python -m http.server`；课前完整跑通并录屏。
- **别在生产仓跑** `ae init`：用专门的空 sandbox。
- **重点不是炫 agent 写代码**，是让大家看见「人在每个节点做判断」——视线落在 **对齐/砍范围、网页验收、handoff** 三处。
- 时间紧时可砍 A3/A4 的露出（口播带过），但 **A1 对齐 和 A6 验证 两步不能省**——它们是本章的论点本身。
