# SOP1：直客订单查询及发票处理工作流

## 目标

输入一个工单号，一键完成跨系统查询，输出订单与发票状态，并在命中异常规则时生成邮件草稿。

该 SOP 是第一阶段的核心交付，优先满足“可跑通、可演示、可复用”的要求，同时为第二阶段平台化沉淀模块边界。

## 用户输入

- `work_order_no`：工单号，例如 `202604273400100002`。

## 涉及系统

| 系统 | 用途 | 备注 |
| --- | --- | --- |
| 服务云 ServiceForce | 按工单号查询客户订单，获取九丘订单号 | 若多个九丘订单号，只取状态为“已支付”的订单 |
| 九丘系统 | 按九丘订单号查询订单详情 | 获取订单状态、PGI、S4 订单号、PGI 抛送 sscm 成功时间 |
| SDI / SPOS | 按平台订单号查询发票链路 | 获取 BTCP 订单号、开票状态、发票类型、发票链接 |
| 邮件系统 | 生成异常处理邮件草稿 | 暂不自动发送，业务人员确认后再发 |

## 主流程

1. 用户输入工单号。
2. 打开服务云，进入“设备服务 / 工单列表”。
3. 按工单号查询，进入历史工单详情。
4. 在“客户订单”栏目获取九丘订单号。
5. 若存在多个九丘订单号，筛选状态为“已支付”的九丘订单号；若没有已支付订单，结果展示为 `/`。
6. 打开九丘系统，进入“订单管理 / 订单查询”。
7. 使用九丘订单号查询，进入订单详情。
8. 获取订单状态、PGI、S4 订单号、PGI 抛送 sscm 成功时间。
9. 通过服务云进入 SDI，再进入 SPOS。
10. 在 SPOS “B2C 销售 / 订单查询”中，以九丘订单号作为平台订单号查询。
11. 查询时间范围建议覆盖到一年前，避免默认两周范围漏查。
12. 获取 BTCP 订单号、开票状态、发票类型、发票链接。
13. 输出结果表。
14. 根据异常规则生成邮件草稿。

## 输出字段

| 字段 | 来源 |
| --- | --- |
| 工单号 | 用户输入 |
| 九丘订单号 | 服务云 |
| 订单状态 | 九丘系统 |
| PGI | 九丘系统 |
| S4 订单号 | 九丘系统 |
| PGI 抛送 sscm 成功时间 | 九丘系统 |
| BTCP 订单号 | SPOS |
| 开票状态 | SPOS |
| 发票类型 | SPOS |
| 发票链接 | SPOS |

## 异常处理规则

| 编号 | 条件 | 处理 |
| --- | --- | --- |
| R1 | 有工单号，无九丘订单号 | 无需额外处理 |
| R2 | 有工单号，有九丘订单号，订单状态不为“已完成” | 无需额外处理 |
| R3 | 订单状态为“已完成”，PGI 或 BTCP 订单号为空 | 生成 BTCP 推送确认邮件草稿 |
| R4 | 订单状态为“已完成”，PGI 抛送 sscm 成功时间为空 | 生成 PGI 推送失败原因确认邮件草稿 |
| R5 | 订单状态为“已完成”，BTCP、PGI、PGI 抛送时间均不为空，开票状态不为“已开票”，发票类型为“数电发票”，发票链接为空 | 生成 IT 确认订单推送是否正常的邮件草稿 |
| R6 | 订单状态为“已完成”，BTCP、PGI、PGI 抛送时间均不为空，开票状态不为“已开票”，发票类型为“数电专票”，发票链接为空 | 生成会计确认发票是否到开票界面的邮件草稿 |

## 多结果处理

一个工单通常对应一个九丘订单，但可能产生两个及以上 SPOS / BTCP 订单。所有 BTCP 订单及其对应状态都需要展示在结果中。

异常处理只生成一次邮件草稿，因为同一工单产生的多个 SPOS / BTCP 订单状态通常一致。

## 当前待确认

1. 文档中九丘订单状态示例有“已成交”，规则中使用“已完成”，需要确认最终判断值。
2. SPOS 入口存在权限或报错问题，需要确认演示账号是否稳定可进入。
3. R5 的 BTCP IT 收件人邮箱待补充。
4. 邮件阶段当前建议只生成草稿，不自动发送。
5. 登录态保存方式待定，建议优先使用浏览器持久化会话，不在代码中硬编码账号密码。

## SOP1 验收标准

1. 用户输入工单号后，可以得到结构化查询结果。
2. 查询失败时能明确标注失败系统、失败步骤和失败原因。
3. 多个 BTCP 订单能完整展示。
4. 命中异常规则时，只生成一份对应邮件草稿。
5. 不命中异常规则时，不生成邮件草稿。
6. 全链路运行日志可追溯，便于现场演示和问题排查。
