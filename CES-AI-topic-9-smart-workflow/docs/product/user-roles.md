# 用户角色

## 1. 业务人员

典型任务：

- 用自然语言创建工作流。
- 在浏览器中录制新平台接口。
- 在“我的录制”中查看和试运行录制节点。
- 将可复用节点同步到节点市场。
- 在“我的流程”中运行已保存 workflow。

关注点：

- 不需要懂 YAML 或代码。
- 能看懂节点输入、输出和运行状态。
- 登录失效时知道如何重新登录。
- 失败提示能说明是配置、登录态、接口、映射还是 LLM 输出问题。

## 2. 业务专家 / SOP Owner

典型任务：

- 判断某条 SOP 是否适合自动化。
- 提供真实系统操作路径和业务字段解释。
- 验证录制节点是否符合业务意图。
- 验证生成 workflow 是否覆盖 SOP 场景判断。

关注点：

- 生成的节点是否保留关键业务参数。
- 输出字段是否有响应证据。
- 场景判断是否按优先级命中，避免重复动作。

## 3. 演示评委 / 管理者

典型任务：

- 在短时间内理解平台扩展逻辑。
- 判断项目是否值得继续平台化投入。

关注点：

- 阶段一真实能力是否可复用。
- 新接口是否真的能录制出来。
- LLM 是否只是设计期辅助，而不是运行期不稳定 Agent。
- 二期是否能站在成熟平台上放大价值。

## 4. 开发 / 联调人员

典型任务：

- 维护节点 schema、workflow schema 和 API。
- 处理录制、LLM、转换、runner、前端承接的断点。
- 将稳定结论沉淀到产品、技术或 ADR 文档。

关注点：

- 证据链完整：录制数据、LLM trace、converted_node、run log。
- 修复集中在根因，不堆兜底。
- 测试覆盖真实失败边界。

## 5. 角色边界

| 能力 | 业务人员 | SOP Owner | 开发/联调 |
|---|---|---|---|
| 录制接口 | 执行操作 | 确认业务含义 | 维护录制链路 |
| 确认节点 | 看输入输出 | 校验字段语义 | 校验 schema/handler |
| 新建工作流 | 输入需求 | 校验流程结果 | 维护 prompt/runner |
| 处理失败 | 按提示重试 | 辅助判断业务异常 | 定位技术根因 |
