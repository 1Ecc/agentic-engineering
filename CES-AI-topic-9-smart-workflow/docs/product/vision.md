# 产品愿景
> 洞察  https://mp.weixin.qq.com/s/VjhOjRhezC8mu7Gl7-3Xnw
> 过去移动互联网时代，核心是「超级 App」；而到了 Agent 时代，更重要的开始变成「任务调度能力」。用户要的未必是停留在哪个入口，而是 AI 能不能真正帮他完成事情。
> 集团内部存在一套高频场景网络，一旦这些能力被 平台 打通，我们会直接演化成 AI 时代的任务操作系统。

## 1. 背景

阶段一交付了 SOP1 直客订单查询及发票处理流程，验证了“一键执行跨系统操作”的可行性。但阶段一仍有两个明显局限：

1. 流程写死：每条新 SOP 都需要开发排期。
2. 接口写死：每接入一个平台接口都需要开发封装 connector。

阶段二的核心问题不是“再写一条 SOP”，而是让平台能逐步长出更多 SOP 能力。

## 2. 一句话定位

面向企业内部 SOP 的 AI 工作流共建平台：把真实系统操作沉淀为节点，再让业务人员用自然语言编排可执行流程。

## 3. 阶段目标

首要目标：

- 证明 SOP1 是平台能力跑出的第一条流程，而不是终点。
- 证明业务人员可通过录制接口沉淀新节点。
- 证明节点可被自然语言编排为工作流。
- 证明执行期不需要 LLM，运行成本和行为可控。

次要目标：

- 沉淀 LLM 编排器、节点注册中心、工作流 runner、节点录制器的架构骨架。
- 为二期迁移到成熟工作流平台底座做概念验证。

## 4. 核心叙事

```text
阶段一：开发录了 3 个接口，写死一条 SOP。
阶段二：业务自己录接口，平台沉淀节点，AI 组装流程，一次设计、稳定复用。
```

## 5. 产品原则

- 真实链路优先：不使用 mock 或 fallback 伪造成功。
- 设计期和执行期分离：LLM 只在设计期参与。
- 节点是一等公民：节点可独立录制、试运行、同步、复用。
- 根因优先：联调问题先定位采集、过滤、LLM、转换、runner 或 UI 中的真实断点。
- Demo 克制：只证明核心主张，不补齐完整企业级平台能力。

## 6. 非目标

- 不做完整拖拽工作流画布。
- 不做复杂 DAG、循环、人工审批、复杂错误恢复。
- 不做权限、多租户、审计、版本管理。
- 不做工作流市场、节点审核、点赞评论。
- 不做节点变更监测和自动修复。
- 不把 SOP1 规则硬编码到 runner 或页面。

## 7. 二期方向

一期 demo 的战略价值是证明“企业工具生产 + AI 自动编排”的核心主张。二期不建议继续完全自研完整平台，而应评估 FastGPT 等成熟开源 AI 工作流平台作为底座：

- 复用画布、节点配置、运行日志、发布和插件生态。
- 保留当前项目的差异化能力：企业系统录制、工具化、登录态、AI workflow compiler。
- 以 SOP1 作为二期 PoC：录制节点服务接入成熟平台，再让 LLM 生成平台 workflow。



## 8. 场景

产品致力扩展 节点市场、skills市场 作为集团的核心能力
1. 确定下高、路径清晰、异常少  → 工作流
2. 中间态    评估ROI  通用能力 vs   SKILLS
3. 高容错、复杂  → SKILLS HUB
