# 节点录制 PRD

## 1. 目标

让业务人员在真实浏览器中执行一次目标操作，平台自动采集业务请求，生成可试调用、可注册、可复用的节点。

核心叙事：

```text
用户操作一次系统 -> 平台捕获请求与响应 -> LLM 生成接口规范草稿 -> 平台转换为节点 -> 节点可被工作流引用
```

---

## 2. 三步向导

### Step 1 描述节点

用户输入：

- 节点名称
- 一句话描述
- 可选目标入口 URL

规则：

- 一句话描述代表用户真实业务意图，LLM 生成时优先级高于请求表面形态。
- 节点名称建议表达平台和动作，例如“服务云查询客户订单号”。
- 如果目标入口 URL 存在，录制浏览器打开该页面；否则打开空页或默认页。

### Step 2 浏览器录制

用户点击“打开录制浏览器”后：

- 后端作为 MCP Client 启动或连接 chrome-devtools MCP。
- 打开用户可操作 Chrome。
- 用户在 Chrome 中完成真实业务操作。
- 前端轮询录制状态。

前端展示：

- recording id
- 模式：MCP 真实浏览器
- 状态：recording / failed / closed
- 已捕获请求数
- 最近请求列表
- 错误信息

多页面规则：

- 支持服务云 -> SDI -> SPOS 这类多页面流程。
- 默认只记录当前业务页。
- 不默认合并所有标签页，避免噪声。
- 当初始页关闭或页面切换时，录制器应选择当前业务页继续采集。

### Step 3 规范确认与试调用

完成录制后：

1. 后端过滤业务请求。
2. LLM 输出 `ApiCaptureSpec`。
3. 平台转换为 `NodeDefinition`。
4. 前端展示节点草稿。
5. 用户输入测试参数试调用。
6. 用户注册节点。

草稿试调用不要求节点先注册到市场。

---

## 3. LLM 生成规则

LLM 不直接输出最终 NodeDefinition，而是输出接口规范草稿。

必须包含：

- 触发动作
- 业务含义
- 选中的证据请求
- query/body 参数清单
- 被忽略参数及原因
- 可选筛选项
- 响应摘要
- 执行 steps
- node mapping 建议

硬约束：

- 用户实际操作中的非空业务参数不能静默丢弃。
- 如果参数不作为输入，必须写入 ignored parameters 并说明原因。
- 空筛选项不强行变成 input，可进入 optional filters。
- `_t`、时间戳、防缓存、token、cookie、authorization 不作为用户输入。
- 没有 response body 证据时，不允许生成阻断后续步骤的必需中间字段映射。

---

## 4. 录制证据规则

原始 recording 应保存：

- 原始 requests
- filtered requests
- LLM 输入摘要
- LLM trace
- converted node

response body 规则：

- 业务响应体必须来自 MCP network detail 的完整 body。
- `responseFilePath` 保存的 body 是主证据。
- telemetry / analytics 上报中的响应片段不能作为主证据。
- LLM token 控制只能作用于 prompt 摘要，不能截断原始落盘证据。

---

## 5. 业务请求过滤

应过滤：

- 静态资源：js、css、png、svg、font。
- analytics、monitor、telemetry。
- login、captcha、auth 噪声。
- config、dictionary、privacy、permission、message center。
- heartbeat、polling、sockjs。

应保留：

- XHR/fetch/GraphQL 业务 API。
- 用户操作触发的非空业务参数。
- 与用户描述匹配的请求。
- 有完整响应体或关键响应结构的请求。

候选排序：

- 用户描述匹配度更高。
- 非空业务参数更多。
- 状态成功。
- 响应体完整。
- 同一路径中优先选择更强证据版本。

---

## 6. 多接口节点

当业务意图需要多个接口完成时，生成 `recorded_http_flow`。

产品规则：

- 支持顺序执行多个步骤。
- 后续步骤可引用前序步骤输出。
- 如果后续请求参数与用户输入相同，且缺少前序响应证据，应优先复用用户输入，不臆造中间字段。
- 草稿节点可直接试调用。

典型场景：

- 服务云通过工单号查询客户订单号。
- 先查列表，再查详情。
- 先查订单，再查发票。

---

## 7. 输出收敛

完整响应体只是证据，不代表最终节点输出要返回完整对象。

规则：

- 输出字段应匹配用户描述。
- 明细数组只输出用户目标字段。
- 对九丘服务产品类数组，输出可投影为 `material_no/pgi/s4_order_no/pgi_to_sscm_success_time` 等目标字段。
- 不默认返回价格、租户、创建时间等未要求字段。

---

## 8. 动态时间

LLM 只能生成白名单时间模板：

```text
{{ time.today() }}
{{ time.now() }}
{{ time.add(time.today(), "-P1Y") }}
```

禁止：

```text
{{ $today }}
{{ $today - 1 year }}
```

用途：

- SPOS 等需要日期筛选的接口。

验收：

- 日期字段不能因不支持模板被渲染为空。
- 未知模板表达式必须校验失败或运行失败，不静默为空。

---

## 9. 错误处理

| 场景 | 用户提示 |
|---|---|
| MCP 未启用/不可用 | 录制启动失败，提示 MCP 配置或连接问题 |
| 浏览器打开失败 | 显示 driver 错误 |
| 录制 0 请求 | 提示未捕获业务 API 请求 |
| LLM key 缺失 | 提示具体 provider key 缺失 |
| LLM 输出不合规 | 展示校验错误和 trace 断点 |
| NodeDefinition 校验失败 | 展示缺失字段或不支持 handler |
| 草稿试调用鉴权失效 | 自动拉起登录浏览器 |
| 输出映射失败 | 展示缺失输出和 mapping |

---

## 10. 注册规则

- 注册成功后节点写入“我的录制”。
- 默认 private，不自动同步市场。
- 用户可在节点市场中手动同步。
- 同名 type 覆盖策略 Demo 期保持简单，后续版本管理另行设计。

---

## 11. 验收标准

- 用户能打开真实浏览器并操作业务系统。
- 录制状态能显示请求计数和最近请求。
- 服务云按工单号查询能保留 `soid` 或语义等价输入。
- 多接口链路能生成 `recorded_http_flow` 并草稿试调用。
- 九丘详情能采集完整 `orderItem[]` 响应证据。
- SPOS 多页面流程不会固定读旧 page。
- SPOS 日期模板使用 `time.*`，不会渲染为空。
- 节点注册后进入“我的录制”，同步后进入节点市场平台分组。
