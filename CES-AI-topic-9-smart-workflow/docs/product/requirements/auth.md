# 鉴权 PRD

## 1. 定位

阶段二不新建鉴权体系，完全复用 SOP1 已验证的浏览器登录态能力。

适用范围：

- SOP1 原始执行。
- 节点录制中的真实业务系统访问。
- 录制节点草稿试调用。
- 节点市场详情试运行。
- 已保存 workflow 运行。

---

## 2. 用户流程

### 2.1 首次登录

1. 用户点击登录或试运行触发鉴权。
2. 系统打开登录浏览器。
3. 用户在浏览器中完成服务云、九丘、SPOS 等平台登录。
4. 用户点击保存登录态。
5. 系统保存本地 storage state。

### 2.2 登录态失效

1. 节点试调用或 workflow 运行返回 `AUTH_REQUIRED`。
2. 前端自动拉起登录浏览器。
3. 用户重新登录目标平台。
4. 保存登录态。
5. 回到原操作重试。

---

## 3. 产品规则

- 登录态失效不能返回空 output。
- 业务 HTTP 200 但 JSON 表示 token 失效，也必须提示重新登录。
- 节点录制、节点试运行、workflow 运行都复用同一套 AuthBar。
- 不在 NodeDefinition 中保存 token、cookie、账号密码或鉴权策略。
- 用户不需要理解 `auth-state.json`，但要能按 UI 完成登录和保存。

---

## 4. 错误提示

| 场景 | 处理 |
|---|---|
| 缺少本地登录态 | 展示需要登录并打开登录浏览器 |
| 服务云 token 失效 | `AUTH_REQUIRED` |
| 九丘 token 失效 | `AUTH_REQUIRED` |
| SPOS loginStatus 未登录 | `AUTH_REQUIRED` |
| 保存登录态失败 | 显示文件或浏览器状态错误 |
| 检查登录态失败 | 显示具体平台状态 |

---

## 5. 验收标准

- 未登录时，录制节点试调用能自动拉起登录浏览器。
- 保存登录态后，同一节点可重新试调用。
- 节点市场试运行与录制 Step 3 试调用行为一致。
- 登录态失效不被映射为空字符串成功。
- 不出现第二套登录方案。
