# 项目目录规划

## 规划原则

1. 先服务 SOP1，不为了平台化提前堆复杂框架。
2. 每个 SOP 都按“输入、连接器、流程、规则、输出、测试数据”拆开，后续自然升级为模块化平台。
3. 系统登录、页面操作、业务规则、邮件模板分层维护，避免把所有逻辑写进一个脚本。
4. 敏感信息与运行产物不进入版本管理。

## 建议目录结构

```text
.
├── README.md
├── reference/
│   └── 原始资料、赛题文档、业务 SOP
├── docs/
│   ├── requirements/
│   │   └── sop1-direct-order-invoice.md
│   └── architecture/
│       └── directory-plan.md
├── apps/
│   ├── web/
│   │   └── 前端界面，负责输入、展示、邮件草稿确认
│   └── api/
│       └── 后端接口，负责触发 workflow 与返回结果
├── packages/
│   ├── workflow-core/
│   │   └── 工作流执行引擎、步骤编排、上下文、日志
│   ├── connectors/
│   │   └── 服务云、九丘、SDI、SPOS、邮件等系统连接器
│   ├── rules/
│   │   └── 业务判断规则与规则测试
│   └── shared/
│       └── 通用类型、工具函数、常量
├── workflows/
│   └── sop1-direct-order-invoice/
│       ├── workflow.yaml
│       ├── rules.yaml
│       ├── email-templates/
│       ├── fixtures/
│       └── README.md
├── tests/
│   ├── e2e/
│   ├── integration/
│   └── unit/
├── scripts/
│   └── 本地调试、录制页面状态、数据初始化脚本
├── data/
│   └── 本地样例数据、临时导出文件，不入库
├── runs/
│   └── 每次执行的日志、截图、结果快照，不入库
└── secrets/
    └── 本地账号、Cookie、Token、会话文件，不入库
```

## SOP1 到平台化的映射

| SOP1 能力 | 平台化模块 |
| --- | --- |
| 输入工单号 | 输入模块：手动输入、文件输入、对话输入 |
| 服务云查询九丘订单号 | 查询模块：服务云连接器 |
| 九丘查询订单详情 | 查询模块：九丘连接器 |
| SDI / SPOS 查询发票信息 | 查询模块：SPOS 连接器 |
| 异常规则判断 | 判断模块：规则引擎 |
| 邮件草稿生成 | 执行模块：邮件连接器 |
| 结果表展示 | 输出模块：表格、导出、接口返回 |
| 运行日志与截图 | 审计模块：执行记录、失败定位 |

## 近期落地顺序

1. 建立 SOP1 的 workflow 配置与字段定义。
2. 实现服务云、九丘、SPOS 三个页面自动化连接器。
3. 实现结果结构化模型。
4. 实现 R1-R6 规则判断。
5. 实现邮件草稿生成。
6. 做一个最小前端页面：输入工单号、执行、查看结果、查看邮件草稿。
7. 增加日志、截图、失败步骤标记，保证演示时可排障。

## 不建议当前阶段投入的内容

1. 暂不做完整拖拽式流程编排器。
2. 暂不做复杂权限系统。
3. 暂不自动发送邮件。
4. 暂不把所有 SOP 都同时实现。
5. 暂不把账号密码写进配置文件或代码。
