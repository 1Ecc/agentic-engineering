# 问题 23：邮件草稿规则路由验证与发送入口

## 问题描述

节点市场已有 `mail.draft` 邮件草稿能力，`我的流程` 中的“直客订单查询与场景判断”工作流也会基于 `rules.first_match` 命中的动作生成邮件草稿。

当前有两个待闭环问题：

1. 暂无真实 case 验证优先级规则路由命中后生成的邮件草稿是否正确。
2. 普通工作流中的 `mail.draft` 节点缺少面向业务人员的节点级发送入口；已有邮件发送 API 能力需要接入到邮件草稿节点体验中。

## 当前态

- `rules.first_match` 已支持按顺序命中第一条规则，并输出 `action`。
- `mail.draft` 已支持基于模板生成 `{ draft }` 输出。
- 后端已有 `/api/mail/send`，前端已有 `sendMail` API 封装和 legacy `EmailDraftPanel` 发送逻辑。
- 普通工作流运行页的节点卡片未接收节点输出，也未在 `mail.draft` 节点上展示发送按钮。

## 期望态

本主题期望态按用户本次指令确认：

- 采用 TDD 验证优先级规则路由下的邮件草稿生成，测试数据使用 mock。
- mock 测试工作流只存在于测试代码，不加入主流程、不写入 `data/workflows`，不影响节点市场或我的流程运行链路。
- 测试运行产生的临时逻辑或数据需要清理；保留必要的回归测试，避免后续规则路由或邮件草稿能力退化。
- 普通工作流只要运行到 `mail.draft` 节点并产出草稿，就在该节点提供“发送邮件”按钮。
- 发送动作复用已有 `/api/mail/send` 能力，由业务人员手动点击触发，不在 runner 或主流程中自动发送。

## 分析与解决

- 规则路由验证应落在 runner 单测：构造 mock 工作流 `data.compose -> rules.first_match -> mail.draft`，覆盖 BTCP 已存在时不误命中 R3、PGI 推送时间为空时按优先级命中 R4 并生成正确草稿。
- 节点级发送入口应落在前端节点卡片：普通工作流运行后把节点 resolved inputs 和 outputs 传入 `WorkflowNodeCard`，卡片检测 `node.type === "mail.draft"` 且 `output.draft` 存在时展示发送按钮。
- 发送入口只做 UI 到 API 的连接，不改 runner 语义，避免把人工确认动作变成自动执行动作。
- 2026-05-19：TDD 红灯发现 `rules.first_match` 的 facts 路径读取不支持数组下标，导致 `order_items[0].btcp_order_no` 已存在时仍被 `empty(...)` 误判为空，从而优先命中 R3。已将规则读取改为和 runner 插值一致的路径解析，支持数组下标。
- 2026-05-19：新增前端共享草稿解析工具，普通工作流运行页把节点 outputs 传入节点卡片；`mail.draft` 节点产出合法草稿后，卡片展示手动“发送邮件”按钮，并复用已有 `/api/mail/send`。
