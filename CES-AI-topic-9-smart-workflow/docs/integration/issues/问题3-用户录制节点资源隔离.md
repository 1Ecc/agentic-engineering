### 问题 3：用户录制节点——应区分「公共共建」与「个人资源」

**问题描述**：

当前录制的节点统一进入节点市场，没有区分公共/个人。实际业务场景下，用户录制的节点应该有两种去向：

1. **同步到节点市场**：作为公共资源，团队其他成员可见可用（⭐ 团队共建）
2. **不同步市场**：仅作为个人资源，只有录制者自己的工作流可引用

同时，当前前端展示区的标题描述不够精准，应使用「用户录制（N）⭐ 团队共建」格式。

**分析与解答**：

当前实现的限制：

1. **存储层**：所有录制节点统一存在 `data/nodes/{type}.json`，无用户隔离概念
2. **数据模型**：`NodeMetadata` 有 `created_by` 字段，但没有 `visibility` / `scope` 字段
3. **前端**：录制流程中没有「是否共享到市场」的选项
4. **注册中心**：`loadDynamic()` 扫描 `data/nodes/*.json` 全量加载，不区分公私

需要的改动：

1. **数据模型扩展**：
   ```typescript
   interface NodeMetadata {
     // ... 现有字段
     visibility?: 'public' | 'private';  // 新增：公共 vs 个人
     created_by?: string;                 // 已有：录制者
   }
   ```

2. **存储隔离**（两种方案）：
   - **方案 A**：目录隔离——`data/nodes/public/{type}.json` + `data/nodes/private/{user}/{type}.json`
   - **方案 B**：字段区分——仍统一存储，查询时按 `visibility` 过滤（Demo 期更简单）

3. **录制流程改造**：Step 3 注册时增加「同步到节点市场」开关（默认 public）

4. **节点市场展示改造**：
   ```
   ▼ 用户录制 · 团队共建（N 个公共节点）⭐
     📹 库存查询  @张三 录制  ·  被引用 8 次
     📹 物流追踪  @李四 录制  ·  被引用 3 次
   
   ▼ 我的录制（M 个私有节点）🔒
     📹 内部报表查询  仅自己可见  ·  被引用 1 次
   ```

5. **LLM 编排器影响**：`generateWorkflow` 的 `availableNodes` 注入需要合并公共节点 + 当前用户的私有节点

**后续优化方向**：

- [ ] `NodeMetadata` 增加 `visibility: 'public' | 'private'`
- [ ] 录制向导 Step 3 增加"同步到节点市场"开关
- [ ] 节点市场分"团队共建"和"我的录制"两个子区域
- [ ] `node-registry.loadDynamic()` 支持按 visibility 过滤
- [ ] LLM prompt 动态注入时合并公共 + 个人节点
