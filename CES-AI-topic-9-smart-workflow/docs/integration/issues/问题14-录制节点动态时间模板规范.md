### 问题 14：录制节点动态时间模板规范

#### bug专题：SPOS 录制节点生成不受支持的日期模板导致请求日期为空

**问题描述**

用户使用 `data/recordings/rec_1778742631123.json` 生成 SPOS 查询节点后，以平台订单号 `RETAIL20260430000023` 测试，结果报错：`spos 请求失败：500`。

排查发现 `parsed_output.steps[0].body_template` 生成了：

```json
{
  "createEndTime": "{{ $today }}",
  "createStartTime": "{{ $today - 1 year }}"
}
```

当前 runner 只支持 `inputs.*`、`steps.*`、`$inputs.*`、`$node.field` 这类引用。`{{ $today }}` 会被当成节点引用解析，找不到节点时静默渲染为空字符串，导致 SPOS 请求体中的日期筛选为空。

**当前态**

- 已通过本地 runner 模板函数确认：`{{ $today }}` 与 `{{ $today - 1 year }}` 会渲染为 `""`。
- SPOS 真实录制成功请求必须带日期筛选，例如 `createStartTime=2025-04-29`、`createEndTime=2026-05-14`。
- 旧模板表达具备业务含义，但不是稳定工程规范：自然语言日期偏移无法明确时区、格式、日历年/天数语义。

**期望态（已与用户对齐）**

- 动态时间采用函数式白名单模板。
- 时间值遵循日期或 RFC3339 风格输出，时间跨度遵循 ISO 8601 duration。
- SPOS 一年前到今天应表达为：

```json
{
  "createEndTime": "{{ time.today() }}",
  "createStartTime": "{{ time.add(time.today(), \"-P1Y\") }}"
}
```

- LLM 只能生成 `time.*` 白名单时间模板。
- validation 必须拦截 `{{ $today }}`、`{{ $today - 1 year }}` 等未知表达式。
- runner 在 recorded_http / recorded_http_flow 渲染请求时使用严格模板模式，未知表达式不再静默变空。

**分析与解决**

根因不是 SPOS 接口本身，也不是录制响应体缺失，而是 LLM 输出的动态日期模板超出了 runner 当前能力边界。

本次实现方向：

- 在 `packages/workflow-runner/src/context.ts` 增加 `time.*` 模板执行能力：
  - `time.today()`：当前本地日期，输出 `YYYY-MM-DD`。
  - `time.now()`：当前本地时间，输出带时区偏移的日期时间。
  - `time.add(value, duration)`：对日期/时间加减 ISO 8601 duration，如 `-P1Y`、`P30D`、`-PT2H`。
  - `time.format(value, format)`：按白名单格式字符串输出。
- 在 recorded_http 请求渲染中启用严格模板模式，未知表达式直接报错。
- 在 LLM ApiCaptureSpec 校验和 NodeDefinition 校验中扫描模板表达式，只允许 `inputs.*`、`$inputs.*`、`steps.*`、`time.*` 白名单。
- 更新 LLM prompt，明确禁止 `$today` 和自然语言时间表达式。
