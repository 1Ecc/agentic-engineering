### 问题 22：我的流程工作流详情与运行体验重构

**问题描述**：

用户提出当前“我的流程 / 运行工作流”的页面重心需要调整：进入某个工作流后，核心不应只是运行表单或运行结果，而应先展示该工作流本身，类似主流工作流平台的工作流详情/编排视图。运行能力应作为工作流详情页右上角的入口，点击后再弹出运行界面，完成输入、执行、输出、节点详情和日志查看。

同时，节点市场的信息顺序也需要调整：当前顺序为“内置通用能力、已接入平台、我的录制”，期望改为“我的录制、已接入平台、内置通用能力”，优先凸显用户自己沉淀的录制节点。

**当前态**：

- 节点市场当前按“内置通用能力 / 已接入平台 / 我的录制”呈现，用户录制节点优先级偏低。
- 我的流程进入运行页后，页面主要围绕“运行工作流”展开，工作流的节点流程虽然存在，但不是页面的第一主视觉。
- 当前运行相关能力更像内嵌在页面中的运行区块，而不是从工作流详情页发起的一次运行任务。
- 当前“最终输出、节点输入输出详情、运行日志/历史记录”之间的层级还不够接近主流工作流平台的运行体验。

**期望态**：

已确认（2026-05-16）：

1. 节点市场
   - 板块顺序调整为：我的录制、已接入平台、内置通用能力。
   - “我的录制”作为用户自定义能力资产，进入节点市场时优先展示。

2. 我的流程 / 工作流详情
   - 从“我的流程”进入某个工作流后，页面核心先展示工作流本身。
   - 工作流呈现使用当前节点流程，作为页面主区域。
   - 页面视觉和信息结构向主流工作流平台靠拢：先看编排，再发起运行。

3. 运行入口
   - 工作流详情页右上角提供“运行”入口。
   - 点击“运行”后从右侧滑出抽屉式运行界面。

4. 运行界面
   - 运行抽屉内先展示该工作流所需输入参数。
   - 用户填写参数后启动运行。
   - 运行完成后展示最终输出。
   - “输出详情”中可查看每个节点的输入和输出。
   - “日志”中展示历史运行记录。

5. 路由与数据
   - 现有 `/workflows/:id/run` 重命名/重构为工作流详情页，不新增平行的独立运行路由。
   - 节点级输入输出详情在运行抽屉内展示，不放到工作流详情页主侧栏。
   - 普通已保存工作流已有运行记录存储：`POST /api/workflows/:id/run` 触发持久化运行，后端写入 `data/runs/<runId>/record.json`；`GET /api/workflows/:id/runs` 返回该工作流最近 5 条历史运行。
   - 草稿试运行当前不持久化；SOP1 专用运行当前使用内存 Map，不走普通工作流历史运行列表。

**分析与解决**：

- 本需求属于“我的流程”整体信息架构与运行体验重构，涉及路由、页面布局、工作流可视化、运行参数表单、运行结果、节点详情和日志展示，不应作为简单样式调整处理。
- 当前先建立 integration 主题作为协作缓冲区，不直接修改产品专题或技术专题。
- 用户已确认路由、运行抽屉、历史日志和节点详情展示位置，可以进入实现。
- 后续实现应优先复用现有页面和数据结构，包括 `WorkflowList.vue`、`WorkflowRun.vue`、`WorkflowPreview.vue`、`NodeMarket.vue`、`WorkflowNodeCard.vue` 以及现有运行记录结构。

已实施（2026-05-16）：

1. 节点市场
   - `NodeMarket.vue` 板块顺序调整为“我的录制 / 已接入平台 / 内置通用能力”。
   - 顶部统计文案同步调整为“我的录制 / 已接入平台 / 内置能力”。

2. 我的流程 / 工作流详情
   - `WorkflowRun.vue` 重构为工作流详情页：进入页面后先展示工作流概览和当前节点流程。
   - 原运行输入、输出、节点详情、日志区域从主页面移入右侧运行抽屉。
   - `WorkflowList.vue` 的工作流卡片主按钮从“运行”改为“打开”，进入 `/workflows/:id`。
   - `App.vue` 新增 `/workflows/:id` 路由，旧 `/workflows/:id/run` 仍保留兼容。
   - `WorkflowPreview.vue` 保存后进入 `/workflows/:id`。

3. 运行抽屉
   - 点击右上角“运行”后从右侧滑出抽屉。
   - 抽屉内包含四个 tab：输入、输出、输出详情、日志。
   - “输入”承接参数填写和启动运行。
   - “输出”展示最终输出和邮件草稿。
   - “输出详情”展示每个节点的配置输入 / resolved inputs / 输出。
   - “日志”展示普通已保存工作流的历史运行记录及历史运行日志。

4. 验证
   - `npm run build` 通过。
   - 已在本地 dev server 验证：
     - 节点市场展示顺序为“我的录制 / 已接入平台 / 内置通用能力”。
     - `/workflows/:id` 可进入工作流详情页。
     - 右上角“运行”可打开右侧抽屉。
     - 抽屉内“输入 / 输出 / 输出详情 / 日志”tab 可切换。

人工验收 bug 修复（2026-05-16）：

1. 阶段 1 与阶段 2 视觉重叠
   - 根因：`.workflow-stage` 固定宽度为 320px，但 CSS Grid 子项默认 `min-width: auto`，节点卡片的最小内容宽度把 grid track 撑到约 382px，导致阶段 1 卡片视觉侵入阶段 2 区域。
   - 修复：在 `.workflow-stage` 中显式设置 `grid-template-columns: minmax(0, 1fr)`，并给 `.stage-nodes` / `.workflow-node-card` 设置 `min-width: 0`，让节点卡片收敛在阶段宽度内。

2. 运行界面输入页繁琐
   - 根因：输入 tab 同时承载运行状态、本次执行日志、认证区和输入表单，信息层级过重。
   - 修复：输入 tab 只保留输入控件和运行按钮。

3. 输出空态观感粗糙
   - 根因：输出 tab 未运行时复用大块 `empty-state`，文案和装饰感过重。
   - 修复：改为轻量等待态，使用旋转 loading 表示结果生成中/等待生成。
