1.1	示例SOP：直客订单查询及发票处理工作流
【背景】
保外直客项目，改变了常规保外交付模式，将由联想直接向用户收费，也将由联想直接给用户开具发票；
目前联想通过联想服务小程序向用户收费，用户完成支付后，可以在小程序中看到维修进程和订单信息，联想在小程序订单明细和短信中展示发票下载链接给用户；
因联想内部系统推送异常，用户小程序登录号码和支付号码不匹配，短信屏蔽忽略等多种场景，时常会有用户通过客服/客诉/工程师反馈我，需求确认订单/发票是否异常并处理，会打断手上的工作，且重复查询会占用较多时间；
故需求输入工单号后，到各系统查询获取订单订单及发票信息，并按照要求输出/处理；

1.3	示例SOP：DFC 服务导入 — 来酷 SN 一键全流程核查工作流
【背景】DFC 服务导入环节，需针对来酷机器 SN，人工核查是否为 DFC 模式、匹配项目与品类、核查产品树绑定状态、判断物码 / 机码并核验发布状态。当前需跨多系统、多共享表手动查询，操作重复、易遗漏、耗时长，需实现输入 SN 一键完成全流程核查，提升服务导入效率与准确性。
【核心目标】
输入来酷机器 SN → 自动完成 DFC 判定→产品树核查→物码 / 机码核验→结果输出 / 自动触发邮件，实现 DFC 服务导入核查标准化、自动化。

【具体操作 SOP】
1）前置要求
•	业务输入：来酷机器 SN
•	系统数据源：2 个业务共享表（DFC 机器范围清单、MTM - 项目 - 品类映射表）
•	对接系统：IPS系统、物码 / 机码管理系统、官网信息展示系统
2）第一步：SN 解析与 DFC 模式判定
•	通过 SN 自动解析获取对应MTM 号
•	在共享表中根据MTM匹配校验是否属于 DFC 模式机器
o	判定结果：非 DFC 模式 → 直接输出 “非 DFC 模式”，流程结束
o	判定结果：是 DFC 模式 → 自动输出该 MTM 对应的项目名称、机器品类
3）第二步：MTM 产品树绑定状态核查
•	调用IPS系统，查询当前 MTM 是否已绑定产品树
o	已绑定产品树 → 输出对应一级产品树、二级产品树、三级产品树
o	未绑定产品树 → 系统弹出输入框，由用户填写一到四级产品树名称并提交
	用户提交后 → 系统自动生成并发送邮件至 Infor 团队，请求将该 MTM 绑定至指定四级产品树
4）第三步：物码 / 机码判定与对应状态核验
•	根据第二步获取的产品树，自动判断为物码类型或机码类型
o	若为物码
	查询该 MTM 是否已创建物码
	查询该 MTM 是否已完成Web Release
	输出物码创建状态、Web Release 状态
o	若为机码
	查询该 MTM 是否已维护机码模式
	查询官网是否已展示对应产品信息
	输出机码模式维护状态、官网展示状态

2.	二阶段需求：功能模块化 
需要具备平台能力和系统功能模块化能力，支持用户在平台中，自主选择模块化能力，进行工作配置，实现工作流智能化；
平台基础功能和操作逻辑概述如下：
 
1.1	功能模块
平台以功能模块为基础设计，功能模块本身包含输入，功能和输出；
【输入】
需要支持多种输入方式
1)	自行输入
支持用户通过对话，在预设位置手动输入；
2)	文档上传
支持用户上传文档，并以对话等形式，系统进行关键字及字段提取，可能需要调取大模型能力；
3)	对话
直接对话输入，系统进行语义理解；
4)	其他功能模块的结果输入
其他功能模块的结果，作为本模块的输入项目，并结合对话等，提取关键字；

【功能】
1）	查询/请求功能
支持对输入物，在预设的网址/系统中进行查询/字段结果请求，并支持结果的筛选；
2）	判断
支持进行对查询的结果进行预设规则的判断
3）	功能执行
支持进行其他系统的功能执行，包含大模型的功能调取；

【输出】
1)	结果
输出物如是文档，则支持查看，下载；流程重复操作时，支持文档更新；
2)	执行结果
执行系统功能的结果反馈
3)	接口链接
生成接口链接允许其他功能模块直接调用

1.2	操作逻辑
1）	通过模块拼接实现流程自动化
支持类似xmind/流程图形式的串联，实现流程的自动化；
2）	模块中按照要求操作
 不同类型的功能模块需要有对应的操作要求：
查询请求模块，需要包含查询的系统/接口，查询的输入物和查询的输出物；
判断模块需要预设规则，即判断内容和规则；
功能执行需要包括具体的系统及对应系统的内容；举例如outlook，支持编辑邮件内容模板及收件人等；大模型需要支持直接调取并输入预设沟通文案等；
